## ADDED Requirements

### Requirement: Структурированные объекты ошибок ДОЛЖНЫ включать метаданные трассировки стека в логах
Система ДОЛЖНА сериализовать ошибки со стеком, которые логируются через `slog`, как структурированные объекты в поле `error`, а не как обычные строки. Структурированный объект ДОЛЖЕН включать `msg`, опциональный `cause` и `stack_trace` как массив кадров, где каждый кадр содержит `function`, `file` и `line`.

#### Scenario: Ошибка залогирована с прямым атрибутом error
- **WHEN** код приложения вызывает `logger.Error(...)` или `logger.Warn(...)` с `"error", err`, и `err` содержит стек
- **THEN** в JSON-логе присутствует `error.msg`
- **THEN** в JSON-логе присутствует `error.stack_trace` как массив объектов кадров
- **THEN** каждый кадр включает `function`, `file` и `line`

### Requirement: Захват стека ДОЛЖЕН выполняться не более одного раза на цепочку ошибок
Механизм захвата стека ДОЛЖЕН избегать дублирующего сбора стека, когда ошибка, уже содержащая стек, оборачивается повторно. Операции оборачивания ОБЯЗАНЫ сохранять исходную причинно-следственную цепочку для `errors.Is` и `errors.As`.

#### Scenario: Повторное оборачивание ошибки с существующим стеком
- **WHEN** ошибка со стеком многократно оборачивается контекстными обёртками
- **THEN** результирующая сериализованная ошибка содержит ровно один логический источник трассировки стека
- **THEN** `errors.Is` и `errors.As` продолжают корректно сопоставлять цели из цепочки оборачивания

### Requirement: Lifecycle-логи observability ДОЛЖНЫ сохранять и код ошибки, и структурированную ошибку
В путях lifecycle-логирования, которые сейчас эмитят `error_code` и `diagnostic_message`, система ДОЛЖНА продолжать эмитить эти поля и дополнительно включать структурированный объект ошибки, когда доступен экземпляр ошибки.

#### Scenario: Событие lifecycle-ошибки воркера
- **WHEN** lifecycle-код воркера эмитит событие ошибки с объектом ошибки
- **THEN** лог по-прежнему включает `error_code`
- **THEN** лог по-прежнему включает `diagnostic_message` (или эквивалентное санитизированное текстовое поле)
- **THEN** лог включает структурированный объект `error` с метаданными трассировки стека

### Requirement: Данные трассировки стека ДОЛЖНЫ быть безопасными и ограниченными
Сериализатор трассировки стека ДОЛЖЕН исключать внутренние кадры runtime/вспомогательных функций и ДОЛЖЕН ограничивать максимальное число кадров фиксированным лимитом для контроля размера логов. Вывод стека НЕ ДОЛЖЕН включать значения переменных или аргументы функций.

#### Scenario: Санитизация стека и контроль лимита
- **WHEN** глубокая цепочка вызовов порождает ошибку со стеком
- **THEN** кадры из `runtime` и вспомогательных функций `internal/stackerr` исключаются из эмитируемого стека
- **THEN** общее число эмитируемых кадров не превышает настроенную максимальную глубину
- **THEN** данные кадра включают только имя функции, путь к файлу и номер строки
