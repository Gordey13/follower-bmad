## Why

В текущем формате логов `slog` поле `error` обычно содержит только строку ошибки, из-за чего расследование инцидентов требует ручного поиска места возникновения сбоя. Нужно добавить машиночитаемый стек ошибок в логи с минимальными изменениями существующего кода и без усложнения инфраструктуры логирования.

## What Changes

- Добавить новый внутренний пакет `internal/stackerr` с API `New`, `Wrap`, `WithStack`.
- Реализовать сериализацию ошибок через `slog.LogValuer`, чтобы `"error", err` автоматически превращалось в структурированный объект (`msg`, `cause`, `stack_trace`).
- Внедрить `stackerr` в приоритетные рантайм-пути (`internal/app/runtime_dependencies.go`, `internal/worker/execution_service.go`, `internal/worker/claim_loop.go`) для захвата стека на границах формирования/оборачивания ошибок.
- Обновить observability-хелперы (в первую очередь `ErrorLifecycleAttrs`) и ключевые call sites, чтобы в lifecycle-логах сохранялся и код ошибки, и структурированная ошибка со стеком.
- Добавить модульные и интеграционные тесты формата логов, совместимости с `errors.Is/As`, и защиты от повторного захвата стека.

## Capabilities

### New Capabilities
- `error-stack-trace-logging`: Единый механизм структурированных ошибок со стеком, автоматически сериализуемых в JSON-логи через `slog.LogValuer`.

### Modified Capabilities
- `<existing-name>`: None.

## Impact

- Затронутые пакеты: `internal/stackerr` (новый), `internal/app`, `internal/worker`, `internal/observability`, частично `cmd/follower` (проверка без изменения контракта запуска).
- Формат логов: поле `error` меняется со строки на объект в местах, где передаётся ошибка как значение.
- Инфраструктура: без новых внешних зависимостей; используется стандартная библиотека (`runtime`, `errors`, `log/slog`).
- Риск: потребители логов, ожидающие строковый `error`, должны поддержать объектный формат; смягчается staged rollout и тестами совместимости.

## Change Notes

- Переход формата логов: поле `error` в путях со stack-enabled ошибками переходит из строкового значения в структурированный объект (`msg`, `stack_trace`).
- Поля `error_code` и `diagnostic_message` сохраняются без изменения контракта.
- Внешние зависимости не добавляются; реализация основана только на стандартной библиотеке Go.
