## MCP Agent Mail — Координация мульти-агентов

Почтовый слой, позволяющий кодинг-агентам асинхронно координироваться через инструменты и ресурсы MCP. Предоставляет идентификации, входящие/исходящие, поисковые цепочки (threads) и совещательные резервирования файлов, с артефактами, проверяемыми человеком в Git.

### Зачем это нужно

- **Предотвращает конфликты:** Явные резервирования (lease) для файлов/шаблонов glob
- **Экономия токенов:** Сообщения хранятся в архиве проекта, не в контексте
- **Быстрые просмотры:** `resource://inbox/...`, `resource://thread/...`

### Рабочий процесс в одном репозитории

1. **Регистрация идентификатора:**
   ```
   ensure_project(project_key=<abs-path>)
   register_agent(project_key, program, model)
   ```

2. **Резервирование файлов перед редактированием:**
   ```
   file_reservation_paths(project_key, agent_name, ["src/**"], ttl_seconds=3600, exclusive=true)
   ```

3. **Коммуникация через цепочки:**
   ```
   send_message(..., thread_id="FEAT-123")
   fetch_inbox(project_key, agent_name)
   acknowledge_message(project_key, agent_name, message_id)
   ```

4. **Быстрые просмотры:**
   ```
   resource://inbox/{Agent}?project=<abs-path>&limit=20
   resource://thread/{id}?project=<abs-path>&include_bodies=true
   ```

### Макросы против гранулярных инструментов

- **Предпочитайте макросы для скорости:** `macro_start_session`, `macro_prepare_thread`, `macro_file_reservation_cycle`, `macro_contact_handshake`
- **Используйте гранулярные инструменты для полного контроля:** `register_agent`, `file_reservation_paths`, `send_message`, `fetch_inbox`, `acknowledge_message`

### Типичные ошибки

- `"from_agent not registered"`: Всегда вызывайте `register_agent` с правильным `project_key` первым делом
- `"FILE_RESERVATION_CONFLICT"`: Скорректируйте шаблоны, дождитесь истечения срока или используйте неэксклюзивное резервирование
- **Ошибки аутентификации:** Если включены JWT+JWKS, добавляйте bearer-токен с соответствующим `kid`

## Beads (br) — Отслеживание задач с учетом зависимостей

Beads предоставляет легковесную базу задач с поддержкой зависимостей и CLI (`br` — beads_rust) для выбора «готовых к работе» задач, установки приоритетов и отслеживания статуса. Это дополняет обмен сообщениями и резервирование файлов в MCP Agent Mail.

**Важно:** `br` неинвазивен — он НИКОГДА автоматически не выполняет команды git. После `br sync --flush-only` вы должны вручную закоммитить изменения.

### Соглашения

- **Единый источник истины:** Beads для статуса/приоритета/зависимостей задач; Agent Mail для обсуждений и аудита
- **Общие идентификаторы:** Используйте ID задачи Beads (например, `br-123`) как `thread_id` в Mail, а темы начинайте с `[br-123]`
- **Резервирования:** При начале задачи вызывайте `file_reservation_paths()` с идентификатором задачи в параметре `reason`

### Типичный поток агента

1. **Выбор готовой работы (Beads):**
   ```bash
   br ready --json  # Выбирайте наивысший приоритет, нет блокировок
   ```

2. **Резервирование области редактирования (Mail):**
   ```
   file_reservation_paths(project_key, agent_name, ["src/**"], ttl_seconds=3600, exclusive=true, reason="br-123")
   ```

3. **Объявление старта (Mail):**
   ```
   send_message(..., thread_id="br-123", subject="[br-123] Start: <title>", ack_required=true)
   ```

4. **Работа и обновление:** Отвечайте в цепочке о прогрессе

5. **Завершение и освобождение:**
   ```bash
   br close 123 --reason "Completed"
   br sync --flush-only  # Экспорт в JSONL (без операций git)
   ```
   ```
   release_file_reservations(project_key, agent_name, paths=["src/**"])
   ```
   Финальный ответ в Mail: `[br-123] Completed` с резюме

### Шпаргалка сопоставлений

| Понятие | Значение |
|---------|----------|
| Mail `thread_id` | `br-###` |
| Mail тема | `[br-###] ...` |
| Резервирование файла `reason` | `br-###` |
| Сообщение коммита | Включайте `br-###` для отслеживаемости |

## bv — Механизм триажа с анализом графа зависимостей

bv — это движок триажа, учитывающий граф зависимостей в проектах Beads (`.beads/beads.jsonl`). Он вычисляет PageRank, betweenness, critical path, cycles, HITS, eigenvector и k-core метрики, работая детерминированно.

**Границы применения:** bv отвечает за *что делать* (триаж, приоритеты, планирование). Для координации между агентами (сообщения, захват задач, резервирование файлов) используйте MCP Agent Mail.

**КРИТИЧЕСКИ ВАЖНО: Используйте ТОЛЬКО флаги `--robot-*`. Запуск `bv` без флагов открывает интерактивный TUI, который заблокирует вашу сессию.**

### Рабочий процесс: Начинайте с триажа

**`bv --robot-triage` — это единая точка входа.** Возвращает:
- `quick_ref`: сводка с общим числом и топ-3 выборами
- `recommendations`: ранжированные элементы с оценками, причинами и информацией о снятии блокировок
- `quick_wins`: лёгкие задачи с высоким эффектом
- `blockers_to_clear`: элементы, разблокирующие наибольшее количество downstream-работы
- `project_health`: распределение статусов/типов/приоритетов, метрики графа
- `commands`: готовые shell-команды для следующих шагов

```bash
bv --robot-triage        # МЕГА-КОМАНДА: начинайте отсюда
bv --robot-next          # Минимальный вариант: только один топ-элемент + команда захвата
```

### Справочник команд

**Планирование:**
| Команда | Результат |
|---------|-----------|
| `--robot-plan` | Параллельные треки выполнения со списками «разблокирует» |
| `--robot-priority` | Обнаружение расхождений в приоритетах с уверенностью |

**Анализ графа:**
| Команда | Результат |
|---------|-----------|
| `--robot-insights` | Полные метрики: PageRank, betweenness, HITS, eigenvector, критический путь, циклы, k-core, точки сочленения, slack |
| `--robot-label-health` | Здоровье по меткам: `health_level`, `velocity_score`, `staleness`, `blocked_count` |
| `--robot-label-flow` | Кросс-меточные зависимости: `flow_matrix`, `dependencies`, `bottleneck_labels` |
| `--robot-label-attention [--attention-limit=N]` | Ранжирование меток по вниманию |

**История и изменения:**
| Команда | Результат |
|---------|-----------|

| `--robot-graph [--graph-format=json\|dot\|mermaid]` | Экспорт графа зависимостей |

### Область действия и фильтрация

```bash
bv --robot-plan --label backend              # Ограничить подграфом метки
bv --robot-insights --as-of HEAD~30          # Исторический снимок
bv --recipe actionable --robot-plan          # Предварительный фильтр: готово к работе
bv --recipe high-impact --robot-triage       # Предварительный фильтр: топ PageRank
bv --robot-triage --robot-triage-by-track    # Группировка по параллельным потокам

```

### Понимание вывода robot-команд

**Любой JSON robot-команд содержит:**
- `data_hash` — отпечаток исходного `beads.jsonl`
- `status` — состояние метрики: `computed|approx|timeout|skipped` + затраченное время в мс
- `as_of` / `as_of_commit` — присутствуют при использовании `--as-of`

**Двухфазный анализ:**
- **Фаза 1 (мгновенная):** степень, топологическая сортировка, плотность
- **Фаза 2 (асинхронная, таймаут 500 мс):** PageRank, betweenness, HITS, eigenvector, циклы

## UBS — Ультимативный сканер ошибок

**Золотое правило:** `ubs <изменённые-файлы>` перед каждым коммитом. Exit code 0 = безопасно. Exit >0 = исправьте и перезапустите.

### Команды

```bash
ubs file.rs file2.rs                    # Конкретные файлы (< 1 с) — ИСПОЛЬЗУЙТЕ ЭТО
ubs $(git diff --name-only --cached)    # Индексированные файлы — перед коммитом
ubs --only=rust,toml src/               # Фильтр по языку (ускорение в 3-5 раз)
ubs --ci --fail-on-warning .            # Режим CI — перед PR
ubs .                                   # Весь проект (игнорирует target/, Cargo.lock)
```

### Формат вывода

```
⚠️  Категория (N ошибок)
    file.rs:42:5 – Описание проблемы
    💡 Предлагаемое исправление
Exit code: 1
```

Парсинг: `file:line:col` → местоположение | 💡 → как исправить | Exit 0/1 → пройти/провал

### Порядок исправления

1. Прочитайте находку → категория + предложение исправления
2. Перейдите `file:line:col` → просмотрите контекст
3. Проверьте, реальна ли проблема (не false positive)
4. Исправьте корневую причину (не симптом)
5. Перезапустите `ubs <file>` → exit 0
6. Закоммитьте

### Серьёзность ошибок

- **Критические (всегда исправлять):** Безопасность памяти, use-after-free, гонки данных, SQL-инъекции
- **Важные (на продакшене):** Паники на unwrap, утечки ресурсов, проверки переполнения
- **Контекстуальные (на усмотрение):** TODO/FIXME, отладочные println!

## ast-grep и ripgrep

**Используйте `ast-grep`, когда важна структура.** Он парсит код и сопоставляет AST-узлы, игнорируя комментарии/строки, и может **безопасно переписывать** код.

- Рефакторинги/кодмоды: переименование API, изменение форм импорта
- Проверки политик: соблюдение шаблонов по репозиторию
- Редактор/автоматизация: LSP режим, вывод `--json`

**Используйте `ripgrep`, когда достаточно текста.** Самый быстрый способ grep’а литералов/регулярных выражений.

- Разведка: поиск строк, TODO, log-строк, значений конфигурации
- Предварительный фильтр: сужение файлов-кандидатов перед ast-grep

### Практическое правило

- Нужна корректность или **применение изменений** → `ast-grep`
- Нужна максимальная скорость или **поиск текста** → `rg`
- Часто комбинируют: `rg` для отбора файлов, затем `ast-grep` для точного сопоставления/модификации

### Примеры для Rust

```bash
# Поиск структуры кода (игнорирует комментарии)
ast-grep run -l Rust -p 'fn $NAME($$ARGS) -> $RET { $$BODY }'

# Найти все вызовы unwrap()
ast-grep run -l Rust -p '$EXPR.unwrap()'

# Быстрый текстовый поиск
rg -n 'println!' -t rust

# Комбинация скорости и точности
rg -l -t rust 'unwrap\(' | xargs ast-grep run -l Rust -p '$X.unwrap()' --json
```

## Morph Warp Grep — Поиск кода на базе ИИ

**Используйте `mcp__morph-mcp__warp_grep` для исследовательских вопросов типа «как работает X?».** AI-агент расширяет ваш запрос, ищет по кодовой базе, читает релевантные файлы и возвращает точные диапазоны строк с полным контекстом.

**Используйте `ripgrep` для точечных поисков.** Когда вы точно знаете, что ищете.

**Используйте `ast-grep` для структурных шаблонов.** Когда нужна точность AST для сопоставления/перезаписи.

### Когда что использовать

| Сценарий | Инструмент | Почему |
|----------|------------|--------|
| «Как работает система резервирования файлов?» | `warp_grep` | Исследовательский поиск; не знаете, с чего начать |
| «Где реализован coalescer коммитов?» | `warp_grep` | Нужно понять архитектуру |
| «Найти все использования `Regex::new`» | `ripgrep` | Точечный поиск литерала |
| «Найти файлы с `println!`» | `ripgrep` | Простой шаблон |
| «Заменить все `unwrap()` на `expect()`» | `ast-grep` | Структурный рефакторинг |

### Использование warp_grep

```
mcp__morph-mcp__warp_grep(
  repoPath: "/data/projects/mcp_agent_mail_rust",
  query: "Как работает система резервирования файлов?"
)
```

Возвращает структурированные результаты с путями к файлам, диапазонами строк и извлечёнными фрагментами кода.

### Анти-паттерны

- **Не используйте** `warp_grep` для поиска конкретного имени функции → используйте `ripgrep`
- **Не используйте** `ripgrep` для понимания «как работает X» → зря потратите время на ручное чтение
- **Не используйте** `ripgrep` для кодмодов → риск побочных правок

## Интеграция рабочего процесса Beads

В этом проекте используется [beads_rust](https://github.com/Dicklesworthstone/beads_rust) (`br`) для отслеживания задач. Задачи хранятся в `.beads/` и отслеживаются в git.

**Важно:** `br` неинвазивен — он НИКОГДА не выполняет команды git. После `br sync --flush-only` вы должны вручную выполнить `git add .beads/ && git commit`.

### Основные команды

```bash
# Просмотр задач (запускает TUI — избегайте в автоматизированных сессиях)
bv

# CLI-команды для агентов (используйте их)
br ready              # Показать задачи, готовые к работе (нет блокировок)
br list --status=open # Все открытые задачи
br show <id>          # Полная информация о задаче с зависимостями
br create --title="..." --type=task --priority=2
br update <id> --status=in_progress
br close <id> --reason "Completed"
br close <id1> <id2>  # Закрыть несколько задач одновременно
br sync --flush-only  # Экспорт в JSONL (без операций git)
```

### Шаблон рабочего процесса

1. **Начало**: Выполните `br ready`, чтобы найти доступную работу
2. **Захват**: Используйте `br update <id> --status=in_progress`
3. **Работа**: Реализуйте задачу
4. **Завершение**: Используйте `br close <id>`
5. **Синхронизация**: Выполните `br sync --flush-only`, затем вручную закоммитьте

### Ключевые концепции

- **Зависимости**: Задачи могут блокировать другие задачи. `br ready` показывает только разблокированную работу.
- **Приоритет**: P0=критический, P1=высокий, P2=средний, P3=низкий, P4=бэклог (используйте числа, не слова)
- **Типы**: task, bug, feature, epic, question, docs
- **Блокировка**: `br dep add <задача> <зависит-от>` для добавления зависимостей

### Протокол завершения сессии

**Перед завершением любой сессии выполните этот чеклист:**

```bash
git status              # Проверить изменения
git add <files>         # Добавить изменения кода
br sync --flush-only    # Экспортировать beads в JSONL
git add .beads/         # Добавить изменения beads
git commit -m "..."     # Закоммитить всё вместе
git push                # Отправить на удаленный репозиторий
```

### Рекомендации

- Проверяйте `br ready` в начале сессии для поиска доступной работы
- Обновляйте статус по мере работы (in_progress → closed)
- Создавайте новые задачи с `br create`, когда обнаруживаете потребность
- Используйте описательные заголовки и задавайте правильный приоритет/тип
- Всегда выполняйте `br sync --flush-only && git add .beads/` перед завершением сессии

**При завершении рабочей сессии** вы ОБЯЗАНЫ выполнить ВСЕ перечисленные ниже шаги.

**ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК:**

3. **Обновите статус задач** — Закройте законченную работу, обновите задачи в процессе
4. **Синхронизируйте beads** — `br sync --flush-only` для экспорта в JSONL
5. **Передача контекста** — Обеспечьте контекст для следующей сессии
