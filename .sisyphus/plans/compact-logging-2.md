# Техническое задание: Упрощение формата логов (версия compact)

## 1. Цель

Снизить информационный шум в текстовых логах приложения, убрав поля, которые в штатном режиме не несут пользы, и сократив длинные идентификаторы. В результате каждая строка лога должна за 3–5 секунд позволять понять: какая задача (`task_id`), какой аккаунт (`account_id`) и что произошло.

## 2. Текущая проблема

Сейчас лог-строка в `compact` формате содержит много повторяющейся информации:

```
18:43:44 INFO  follow.action.clicked  component:worker.claim_loop task:…d324ad6a account_id:33e5fb53-e663-bcf2-6f08-0071383dd559 attempt:1 error_code:eligible follow_outcome:follow_completed (17222ms)
```

- Поля `attempt:1` и `error_code:"eligible"` присутствуют в **каждой** успешной операции и не дают новой информации.
- `account_id` выводится полностью (36 символов) — трудно читать и визуально сравнивать.
- Формат времени без миллисекунд не позволяет оценить порядок событий внутри секунды.
- Длительность выводится в скобках `(17222ms)` — менее наглядно, чем `+17222ms`.

## 3. Требования к формату

### 3.1 Временная метка
- Формат: `HH:MM:SS.mmm` (миллисекунды обязательны).
- Пример: `18:43:44.710` вместо `18:43:44`.

### 3.2 Имя события (`msg`)
- Должно выводиться в квадратных скобках, без кавычек и служебных символов.
- Пример: `[follow.action.clicked]` вместо `follow.action.clicked`.

### 3.3 Идентификаторы
- `task_id`: выводить только последние 8 символов, перед ними поставить `…` (три точки).
- `account_id`: выводить только последние 8 символов, перед ними `…`.
- Ключ поля: для `account_id` использовать сокращение `acc:` (вместо `account_id`).
- Пример: вместо `account_id:33e5fb53-e663-bcf2-6f08-0071383dd559` выводить `acc:…3dd559`.
- **Важно:** если по последним 8 символам возникают коллизии (редко, но возможно), допускается брать первые 8 символов либо 6+6. Выбрать `… + последние 8`, это достаточно для визуального различия соседних задач.

### 3.4 Шумовые поля
- Поле `attempt`: **не выводить**, если его значение равно `1`. Если `attempt > 1` (повторная попытка) — выводить как `attempt:N`.
- Поле `error_code`: **не выводить**, если его значение равно `"eligible"`. Если значение другое (например, `"timeout"`, `"network_error"`) — выводить как `error_code:…`.

### 3.5 Длительность
- Вместо скобок `(1234ms)` использовать формат `+1234ms` (знак плюс и сразу число).
- Если поле `duration_ms` отсутствует в событии — не выводить.

### 3.6 Прочие поля
- Поля, не перечисленные выше (например, `follow_outcome`, `component`, `status`, `session_revision`), **должны сохраняться** в том виде, как сейчас, но без изменений.
- Исключение: если поле пустое или равно значению по умолчанию, можно опустить.

## 4. Примеры желаемого вывода
**Стало:**
```
18:43:44.710 INFO  [follow.action.clicked]  component:worker.claim_loop task:…d324ad6a acc:…3dd559 follow_outcome:follow_completed +17222ms
18:43:48.000 INFO  [task.succeeded]  component:worker.claim_loop task:…a08adb2e acc:…3dd559 status:success +0ms
```
**Пример ошибки (где `error_code` не `eligible`):**

```
18:45:10.123 ERROR [follow.execution.failed]  component:worker.claim_loop task:…deadbeef acc:…ba98ef error_code:timeout +30000ms
```

## 5. Требования к реализации

- **Место изменения:** пакет, отвечающий за `compact` формат логов (вероятно, `logger/compact_handler.go` или аналогичный).
- **Не менять** другие форматы (JSON, текстовый full), если они используются.
- **Не менять** бизнес-логику и структуру полей в самом событии — только форматирование при выводе.
- Проверить, что при форматировании не теряются важные поля (например, `follow_outcome`, `status`, `session_revision`).
- Функция сокращения ID должна быть безопасной: если строка короче 8 символов, выводить всю строку без добавления `…`.

## 6. Критерии приёмки

1. В логах **отсутствуют** поля `attempt:1` и `error_code:eligible`.
2. Поле `attempt` появляется только если значение **больше 1**.
3. Поле `error_code` появляется только если значение **не равно** `"eligible"`.
4. Временная метка содержит миллисекунды (три цифры после точки).
5. Сообщение выводится в квадратных скобках.
6. `task_id` сокращён до вида `…XXXXXXXX` (8 символов).
7. `account_id` сокращён до вида `…XXXXXXXX` и называется `acc:`.
8. Длительность выводится как `+Nms`.
9. Приложение компилируется и проходит существующие тесты (можно обновить тесты под новый формат, но не сломать сборку).
10. Ручная проверка: запуск приложения в тестовой среде с реальными задачами даёт вывод, соответствующий примерам.
